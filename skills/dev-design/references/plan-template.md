# Native dev generated-plan template

Use native Plan mode to generate one plan. The path returned by `ExitPlanMode` is the exact-byte
approval boundary; do not copy this template to `.planning/PLAN.md` or create a visible verdict.

```markdown
# [Feature] implementation plan

## Intent and Scope
- Outcome: ...
- In scope: ...
- Exclusions: ...

## Requirements
- REQ-01: ...

## Chosen Architecture
- Selected option: ...
- Rationale and accepted trade-offs: ...
- Boundaries/interfaces: ...

## Testing Strategy and Real-Test Contract
- Framework and exact command: ...
- User workflow / production protocol / visible result: ...
- First failing test and expected RED: ...
- Full-suite or E2E command: ...

## Implementation Tasks
### TASK-01: [name]
- Dependencies: none
- Work: Observe the named RED first; then implement only this boundary.
- Criteria: ...
- Outputs: `path/to/output`
- Writable paths: `path/to/output`
- First failing test / RED expectation: ...
- Verify command: `...`
- Instruction files: `/absolute/path/to/instructions.md`
- Model: ...
- Effort: ...

## Requirement → Test Map
| Requirement | Tasks | Test / evidence command |
|---|---|---|
| REQ-01 | TASK-01 | `...` |

## Evidence Plan
- REQ-01: ...

## Review Surfaces
- Correctness/regression: ...
- Security/compatibility/API/UI as applicable: ...
```

Every behavioral requirement must have a `REQ-NN`; every task must have a `TASK-NN`. Task fields
compile directly to the shared TaskContract. Dependencies must be an acyclic DAG, and all output
and writable paths must be concrete repo-relative paths. A requirement, architecture, dependency,
test contract, or evidence change needs a new generated plan and fresh receipt.
